# MRX1000 pillar-support fast lane — September 24, 2026

Purpose: increase publication throughput without treating generated titles, crawler eligibility, or an IndexNow receipt as proof of search ranking or ChatGPT citation. Codex remains the sole writer of the verified release worktree.

## Select by answer gap, not title count

For each candidate, lock a named primary pillar, one narrow owner question, an answer object, and at least one useful reciprocal pillar/support link before drafting. Screen the live corpus for the same answer in existing guides. Reject state-name swaps, broad duplicates, unsupported claims, and topics whose source role cannot be explained. Use Search Atlas topical maps as idea inventories; demand and generated text are not approval. Record the source date and what each primary source can and cannot establish.

## Prepare independent packets, release efficiently

Each article keeps its own exact-title identity, source and originality review, factual/citation and compliance receipts, one unique hero bearing the locked title, that same hero for page/OG/Twitter, and a distinct in-body image. Run cheap schema, FAQ-parity, citation, image-hash, and pillar-link checks before the expensive full build. Keep drafting the next distinct packet while a previous release's audit processes; do not change a published-and-final-recrawl-verified count based on aggregate audit totals.

When multiple packets are independently ready, release them together through one full test/build/deployment and one post-release recrawl. Do not hold a ready article merely to fill a batch. Verify every new article, image binary, canonical, source link, and reciprocal pillar card on every active production hostname; submit only the new exact canonical URLs once to IndexNow. Then wait for a terminal completed/postprocessed audit and fresh OTTO dashboard. Record OTTO pending proposals, generated previews, and raw audit observations separately. A new release does not justify reapplying rejected OTTO suggestions or starting a blind second crawl.

## Measure the right speed and discovery outcomes

Track time from distinct-answer admission to live verification, number of quality-gated articles per release, avoidable gate rework, pillar backlink coverage, and exact successful/indexable Page Explorer rows. Search Console impressions and observed assistant referrals/citations are separate outcome evidence when actually available. Public canonical HTML, sitemap membership, source-backed answer text, OAI-SearchBot eligibility, and MRX public MCP discoverability are useful prerequisites; none guarantees ChatGPT retrieval or a citation.

Its first public draft was held for FAQ duplication/mismatch and a missing assessor source; those were corrected before release. The append-only identity test was made data-driven so a new admitted row no longer requires copying an expected-row array. Further build/staging automation should preserve the same signed-input checks and be verified before it replaces explicit inputs.
