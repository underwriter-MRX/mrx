## Build a source-conflict log before asking for clarification

A useful conflict log separates observation, question, and resolution evidence.

| Field | What to record |
| ----- | -------------- |
| Publisher surface | Exact URL, page heading, link text, retrieval date, and optional page capture hash |
| Download identity | Exact target URL, response result, ZIP bytes, and ZIP SHA-256 |
| Member identity | Exact member name, PDF bytes, PDF SHA-256, page count, geometry, encryption, and rotation |
| Controlling render | Physical page number, render dimensions, render SHA-256, and manually verified wording |
| Conflict statement | `Publisher page groups link as certified; physical page 1 says preliminary` |
| Unresolved question | Which status and scope did Martin CAD intend for this member on the retrieval date? |
| Exclusion boundary | Physical pages 2 through 2,225 contain record-specific output and remain nonpublic |
| Later response | Issuer, date, response channel, exact wording, attachments, and separate hashes |

Do not place an anticipated answer in the resolution field. Do not convert a phone summary into a formal issuer statement. If the issuer supplies a revised file or written clarification, keep it as a new dated item linked to the original capture.

This approach preserves information gain for search and answer systems because it states the exact conflict, evidence surfaces, and limits in a compact form. It also avoids a false certainty that another publisher, researcher, or model could repeat as fact.
