The direct answer is: open **`2. MINERAL FILE LAYOUT.pdf` first**. It is the smallest document that explains how the record-level files are organized and which field categories they contain. Then use **`5. MINERAL RECAP.PDF`** only for aggregate context. Do not begin by opening the enormous TXT or CSV member merely because it is available.

That order matters because the layout identifies owner name, mailing-address, account, acreage, decimal-interest, privacy-code, electronic-communication, and email-address fields. A researcher should define a legitimate task and privacy-safe handling process before touching record-level rows.

## PDF, TXT, and CSV are different handling surfaces

The archive offers three large record-facing formats, but availability does not make them interchangeable.

### Mineral appraisal-roll PDF

The 59,284,432-byte appraisal-roll PDF is a presentation format. It may be easier for a person to view, but searching, copying, or interpreting a row still requires a defined account question and care around personal data. A visible row is not a title determination.

### Flat-text file

The 1,000,697,491-byte TXT file appears intended for fixed-position processing with the layout document. A tool that treats it as ordinary delimited text could shift or concatenate fields. A small parsing error can become a large, confident-looking data error.

### CSV file

The 1,324,112,959-byte CSV file appears intended for tabular import. Before loading it, a researcher would still need to verify encoding, delimiter and quoting behavior, headers, row counts, null handling, field parity with the layout, and treatment of personal fields. This article did not perform that import.

No row from any of these three members was opened, extracted, sampled, searched, copied, or reproduced for this article. The archive central directory and control documents supplied enough evidence for the article’s bounded job.

## A privacy-aware archive workflow

Use this sequence when the official archive is relevant to a defined research task:

1. **Record the source route.** Save the official page URL, archive URL, retrieval time, response metadata, bytes, and SHA-256.
2. **List members without extracting them.** Capture exact names, compressed and uncompressed sizes, dates, and archive structure.
3. **Open the layout first.** Identify record length, field categories, personal fields, account identifiers, and source-defined codes.
4. **Open the recap second.** Use only source-labeled aggregate context; do not convert it into owner or property counts.
5. **Define the exact question.** Name the account, field, comparison, date, and reason before touching row-level data.
6. **Minimize the data.** Extract only fields and rows required for the task. Keep personal contact fields out unless they are genuinely necessary and authorized.
7. **Keep a transformation log.** Record parsing rules, filters, joins, renamed columns, exclusions, errors, and unresolved mismatches.
8. **Separate source facts from conclusions.** A row may support a bounded appraisal-record observation; it does not by itself prove ownership, title, private value, or a transaction result.
9. **Ask the issuer.** Use Midland CAD for official definitions, corrections, current-file questions, and interpretation of district codes.

The [Texas Comptroller Midland county directory](https://comptroller.texas.gov/taxes/property-tax/county-directory/midland.php) identifies Midland Central Appraisal District and routes users to `midcad.org`. That supports issuer provenance. It does not endorse every archive member or validate a particular record.

## What this archive does not answer

Do not convert a certified-roll archive into any of these conclusions:

| Unsupported conclusion                       | Separate evidence still required                                                                     |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| A person currently owns a mineral interest   | Current title chain, instruments, conveyance interpretation, and qualified title review              |
| A row applies to the intended tract          | Account, legal-description, tract, lease, and property crosswalk                                     |
| The appraisal is accurate or final           | Current district record, method, supporting data, corrections, protest status, and official response |
| Appraised value equals private sale value    | Interest, title, lease, production, risk, timing, market, and transaction evidence                   |
| A bulk file is complete and current          | Issuer definitions, as-of date, inclusion and exclusion rules, corrections, and replacement checks   |
| A privacy code authorizes disclosure         | Current official interpretation and applicable qualified privacy or legal review                     |
| A CSV import preserved every field correctly | Encoding, delimiter, quoting, row-count, field-parity, and transformation controls                   |
