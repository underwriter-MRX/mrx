> **Historical table interpretation, not a current rule decision.** This page explains selected fields in a dated Texas Railroad Commission export manual. It does not decide which rule or order currently governs a well, permit, lease, tract, depth, operator, owner, or proposed location. MRX may have an economic interest in a later mineral transaction. When that applies, the buyer relationship is disclosed in writing before an agreement is signed.

The direct answer is: **in the reviewed historical export, start with <code>og_field_rule</code> for field-specific rule rows and use <code>og_std_field_rule</code> only for the standard fallback path described by that manual**. Keep base and optional rows separate. Keep the source class, depth band, spacing fields, effective date, and gas-rule rescission date separate too.

That result is a historical data interpretation, not proof of the rule that governs a real well or permit today. Verify current applicability through the live Field Rules Query, current Texas Administrative Code, relevant final or special orders, and qualified review.

## The two rule tables answer different questions

The [RRC Oil and Gas Field Information data dictionary](https://rrc.texas.gov/media/01wfdxlx/oilgasfieldrules.pdf) describes an Oracle export dated August 10, 2005. In that source, the rule tables have distinct roles:

| Historical table               | Source-described role                                                                                 | Safe interpretation                                                                                  |
| ------------------------------ | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| <code>og_field_rule</code>     | Field-specific base and optional rule rows                                                            | Preserve every matching row, its oil-or-gas role, depth context, values, and effective date          |
| <code>og_std_field_rule</code> | Standard rule rows applied when field-specific rules are absent under the manual's fallback procedure | Preserve the selected standard class and exact lookup reason; do not present it as a current opinion |
| <code>og_field_info</code>     | Type-specific field information, including source-class and rescission fields                         | Keep it linked by exact source keys and oil-or-gas context; do not merge it into a rule row          |

The presence or absence test comes first. The manual says a field with special field rules has a row in <code>og_field_rule</code> and uses those field-specific rules. When that row is absent, its documented standard-rule lookup is used. A blank result in a copy, filtered extract, or query view does not prove that a controlling rule never existed.

## Preserve field-specific base and optional rows

The <code>og_field_rule</code> definition includes <code>oil_or_gas_code</code>, <code>field_id</code>, <code>field_rule_id</code>, <code>rule_type_code</code>, spacing and acreage fields, diagonal fields, depth-related context, and <code>effective_dt</code>. Its data dictionary defines <code>rule_type_code</code> as base (`b`) or optional (`o`).

Do not translate base and optional into primary and superseded. Those are different words with unsupported consequences. Preserve the source value, row identity, and related fields, then ask what the current query and order history show.

A defensible extract keeps one record per source row:

| Evidence field               | Record                                                                                   |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| <code>source_table</code>    | <code>og_field_rule</code>                                                               |
| <code>field_id</code>        | Exact source key                                                                         |
| <code>field_rule_id</code>   | Exact rule-row key                                                                       |
| <code>oil_or_gas_code</code> | Exact row role                                                                           |
| <code>rule_type_code</code>  | Raw base or optional value                                                               |
| <code>depth_scope</code>     | Exact source depth field or linked standard interval, without invented conversion        |
| <code>spacing_fields</code>  | Lease distance, well distance, acres per unit, tolerance, and diagonal fields as present |
| <code>effective_dt</code>    | Raw source date plus normalized display date                                             |
| <code>source_object</code>   | File or query identity, version, access time, and retained hash                          |

If two rows exist, retain both. If a value is blank, keep it blank and label the evidence gap. Do not fill it from a different field, oil-or-gas role, depth interval, manual, or current page merely because the headings look similar.

## Read the historical fallback sequence exactly

For fields without field-specific rows, the manual states this historical order:

1. If the field's discovery county is McCulloch County, use the McCulloch County rules.
2. Otherwise, if the field is in district 7B or 09, use county-regular rules.
3. In all other cases, use statewide rules.

That sequence belongs to the dated export description. It is not a free-standing rule engine for current work. Record both the selected historical class and why the source procedure selected it.

The same manual defines <code>derived_rule_type_code</code> labels for county regular (`Cr`), McCulloch County (`Mc`), special (`Sp`), and statewide (`Sw`). The <code>og_std_field_rule</code> table separately includes a standard-rule code, a standard-rule row ID, minimum and maximum depth, lease and well distances, and acres per unit.

Do not collapse these fields:

- <code>rule_type_code</code> says base or optional for a field-specific rule row.
- <code>derived_rule_type_code</code> records the source class described for field information.
- <code>std_field_rule_code</code> identifies a standard-rule category.
- <code>std_field_rule_id</code> identifies a relative row within that category.

The labels may look like one hierarchy, but each comes from a different field and has its own function.

## Treat effective and rescission dates as different events

The historical schema places <code>effective_dt</code> on <code>og_field_rule</code>. It places <code>rescind_dt</code> on <code>og_field_info</code>. The dictionary describes <code>rescind_dt</code> as the date gas rules were rescinded and the gas field reverted to statewide spacing rules.

That wording supports a bounded record:

`gas-rule row → source rescission date → source-described reversion to statewide spacing`

It does not establish that every other field rule, order, product role, depth interval, exception, or permit consequence ended on the same date. A historical rescission date is also not a substitute for the current query or current rules.

Use distinct audit fields:

| Date field                           | Meaning in the reviewed source                                  | Do not infer                                                 |
| ------------------------------------ | --------------------------------------------------------------- | ------------------------------------------------------------ |
| <code>field_rule_effective_dt</code> | Effective date carried on a field-specific rule row             | Current validity, priority, or complete order history        |
| <code>gas_rule_rescind_dt</code>     | Date the manual says gas rules were rescinded                   | Rescission of every oil rule, order, exception, or condition |
| <code>source_export_dt</code>        | August 10, 2005 Oracle export date                              | Date the current RRC system was last updated                 |
| <code>retrieval_accessed_at</code>   | When the reviewer obtained the current page, query, or document | Effective date of a legal rule                               |

## Separate historical schema from current evidence

The current [RRC download catalog](https://www.rrc.texas.gov/resource-center/research/data-sets-available-for-download/) lists Oil & Gas Field Rules as a monthly dataset and describes it as spacing and production rules for a producing area with a common reservoir. The current [Field Data page](https://www.rrc.texas.gov/oil-and-gas/research-and-statistics/field-data/) separately links the Oil & Gas Field Information Query and Proration Schedule by Field.

The [RRC Online Research Queries page](https://www.rrc.texas.gov/resource-center/research/research-queries/) lists the Field Rules Query as a nightly-updated route. It also says online datasets are continually updated, informational, not authoritative public records, and have no legal force or effect. Users remain responsible for accuracy, completeness, currency, and suitability.

Those current pages establish available routes and source limitations. They do not prove that a historical table row remains current.

The [RRC Current Rules page](https://www.rrc.texas.gov/general-counsel/rules/current-rules/) identifies the Texas Administrative Code as the official rules source and warns that printable chapter PDFs are informational snapshots. When a current rule question matters, preserve the official rule route, the access date, the applicable section, and the facts that connect it to the field and proposal.

## Use order history for special-rule context

The [RRC Oil and Gas Well Records page](https://www.rrc.texas.gov/oil-and-gas/research-and-statistics/obtaining-commission-records/oil-and-gas-well-records/) says hearing files can cover new field designations, statewide rules, field rules, and exceptions. Depending on the file, materials can include a notice of hearing, final or special order, maps, engineer notes, reservoir data, and exhibits.

The [RRC Drilling Permits W-1 Online Filing User Guide](https://rrc.texas.gov/media/qqmhxxex/dpmanual.pdf) shows that the field-rules display can separate oil, gas, and special horizontal rule sections and can provide a final-order link in its history area for fields with special rules. The guide also distinguishes statewide, county-regular, and special-field-rule contexts in the permit workflow.

This article does not retrieve or interpret a particular order. Instead, it preserves a stop condition: if current applicability, spacing, density, an exception, or a permit depends on a special rule, identify the exact current field and depth, retrieve the live rule display, retain the cited order, and obtain qualified review.

| <code>review_status</code>               | Historical interpretation only, current-source checked, or specialist stop        |

Do not use `not located` as `not applicable`. Do not use a found row as `currently controlling`. Those conclusions require additional evidence.

## Reconcile without overwriting evidence

When historical and current sources differ, keep both:

1. Hash and retain the historical manual or export used.
2. Record the historical row path without editing its labels or dates.
3. Capture the current query route, criteria, access time, and result state separately.
4. Identify any matching field number, name, district, product role, and depth without converting a partial match into identity.
5. Retrieve a cited final or special order when current applicability depends on it.
6. Record the current TAC section separately from the field-specific evidence.
7. Classify the outcome as `historical_only`, `current_route_checked`, `source_changed`, `order_needed`, `ambiguous`, or `qualified_review_stop`.

Never delete the older record because a newer page exists. Version differences are evidence about the research path.

## Stop before a private or regulatory conclusion

The field-rule tables do not establish:

- that a proposed well is regularly located;
- that a spacing or density exception is or is not required;
- that an operator may drill or complete a well;
- that a special order applies to every depth or product role;
- that a field row is complete, current, authoritative, or legally controlling;
- that a lease, tract, unit, or owner is connected to the field; or
- that a mineral interest has a particular production profile, reserve, value, offer, or transaction outcome.

Those are different jobs with different evidence. ## Frequently asked questions

### What is the difference between og_field_rule and og_std_field_rule?

In the reviewed historical export manual, <code>og_field_rule</code> stores field-specific base or optional rule rows. <code>og_std_field_rule</code> stores standard rule rows used when the historical lookup does not find field-specific rules. This describes that export, not a current legal determination.

### What was the historical standard-rule fallback order?

The manual says to use McCulloch County rules when the discovery county is McCulloch, county-regular rules for a field in district 7B or 09, and statewide rules otherwise. Preserve this as a dated source rule and verify current applicability separately.

### Does rule_type_code say whether a rule is special or statewide?

No. The manual defines <code>rule_type_code</code> as base or optional for an <code>og_field_rule</code> row. It separately defines <code>derived_rule_type_code</code> values for county regular, McCulloch County, special, or statewide source classes.

### What does rescind_dt mean?

The reviewed manual describes <code>rescind_dt</code> as the date gas rules were rescinded and the gas field reverted to statewide spacing rules. Record the date and source context; do not assume it resolves every current rule, order, depth, or permit question.

### Can I use this article to decide whether a well needs a spacing exception?

No. That decision depends on current field information, current rules, the applicable field and depth, any special order, the proposed location, and the actual filing facts. Use the current RRC systems and qualified review.
